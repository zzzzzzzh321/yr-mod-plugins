# SDK 功能测试地图

这是一张自制的 48×48 平地实验地图，用同一个 VERA20K 引擎测试原版行为、兼容护盾和过载护盾。只引用玩家本机的尤里的复仇素材，不附带原版或心灵终结资源。

地图规则写在 [sdk-feature-lab.map](sdk-feature-lab.map) 中；[spawn.ini](spawn.ini) 配置一名玩家和一个电脑。电脑没有初始部队和资金，只保留一个不可出售的电厂，避免对局自动结束或出售建筑产生的士兵干扰实验。地图单位禁止被 AI 队伍征用。

## 启动

本机整理的验收包包含 `00-原版对照.cmd`、`01-兼容护盾.cmd`、`02-过载护盾.cmd`，可以直接双击。它们已填写这台电脑的原版游戏路径；换机器时修改其中的路径。以下命令用于从源码目录启动。

需要 Python 3、兼容 SDK API v1 的 VERA20K 引擎和原版 YR 资源目录。兼容／过载模式使用本工程生成的 `vera20k-ares.wasm` 与同目录的 `vera-mod.json`，建议组件版本 0.4.1 或更新版本。

在本目录执行，路径按本机情况填写：

```sh
python play.py --engine /path/to/vera20k --game-dir /path/to/YR --component /path/to/vera20k-ares.wasm --mode compatible
```

Windows 的引擎文件名为 `vera20k.exe`。三个模式使用相同地图与引擎：

| `--mode` | 加载方式 | 用途 |
| --- | --- | --- |
| `vanilla` | 不提供组件声明和 Wasm | 原版对照，不需要 `--component` |
| `compatible` | 开启护盾和三项 Ares 弹药功能，关闭过载 | 验证兼容机制 |
| `overload` | 在 compatible 基础上开启过载 | 比较作者自定义的护盾行为 |

默认全屏、100% 战场缩放；加 `--windowed` 使用窗口。低分辨率下可将鼠标移到画面边缘滚动查看其余区域。每次启动产生一个独立运行目录，配置、日志和存档都保存在那里，不向原版资源目录写文件。`--work-dir` 指定这些目录的父目录；`--detach` 启动后立即返回；`--dry-run` 只校验启动数据。

启动器通过引擎已有的 `--community-launch` 内存资源协议提供地图和组件，直接进入对局。它在内存中切换 `Overload`，不修改地图源文件。不能只把地图复制到原版目录就认为外置插件也已加载。

## 六个测试区

矿石字母标记 A—F，从上到下排列为两列：

```text
A  原版伤害对照       B  护盾／恢复／过载
C  每发弹药成本       D  普通与空仓装填
E  低弹量切换武器     F  护盾＋弹药组合
```

每区都有一辆可控制的己方车辆，右上方是对应靶车。除 F 区对手外，靶车不还击。单位名称和外观沿用原版，用字母与位置区分，避免覆盖原版语言文件。鼠标移到目标上观察血条；选择己方单位观察弹药格。按 `S` 停火；重新运行对应启动命令重置实验。

犀牛外观的靶车保留炮塔，但不配置武器；坦克歼击车沿用原版固定炮管。测试弹头使用原版 `S_CLSN16`／`S_CLSN22` 命中动画，动画不附加伤害，弹药与护盾实验的伤害参数保持不变。武器的 `Anim=GUNFIRE` 是炮口动画，命中动画由弹头的 `AnimList` 决定。

| 区域 | 己方单位／起始格坐标 `(X,Y)` | 操作与预期现象 |
| --- | --- | --- |
| A | 灰熊外观，`(38,46)` | 攻击右上方无盾靶车。靶车生命 300，每次命中伤害 60，作为对照。 |
| B | 灰熊外观，`(46,38)` | 左上与右上两辆靶车均为生命 300、护盾 100；下方第三辆靶车初始护盾 25，会自行恢复。先用 compatible 模式测试，再重开 overload 比较。 |
| C | 狂风外观，`(45,53)` | 满弹药 5，每发消耗 2。持续攻击时出现 `5→3→1`，余量不足再射击，等待装填后才能继续。原版模式每发只消耗 1。 |
| D | 犀牛外观，`(53,45)` | 满弹药 6，每发消耗 6。射击一次后按 S：空仓先装入 3，之后每次装入 2，最终补满至 6。 |
| E | 光棱外观，`(52,60)` | 满弹药 6，主武器每发消耗 2。持续攻击，弹药 `6→4→2→0` 后应改用不耗弹药的青色激光；装填后再次使用主武器。 |
| F | 坦克歼击车外观，`(60,52)` | 同时具有护盾、每发成本 2、装填数量和备用武器。攻击右上方对手，对手会还击；观察攻防机制共同运行。最后测试本区。 |

C、D、E 的靶车生命为 20,000，可反复使用。F 的对手同样为 20,000，己方仍为生命 300，因此持续交火会被击毁，不是无敌演示。

## 护盾与过载如何比较

以下是本地图配置的预期序列，要求连续命中，期间未发生恢复：

| 目标／模式 | 初始生命 | 第 1 次命中 | 第 2 次命中 | 第 3 次命中 |
| --- | --- | --- | --- | --- |
| A：无盾对照 | 300 | 240 | 180 | 120 |
| B：兼容护盾 | 300 | 300 | 280 | 220 |
| B：过载护盾 | 300 | 300 | 240 | 180 |

兼容模式中，第一发由护盾吸收 60，第二发先打掉剩下的 40，再对本体造成 20。第二发后按 S 停火，可观察护盾破坏后的重生：等待 360 个逻辑帧恢复 50 点护盾，之后继续自愈。

过载模式中，第一次吸收 60 点就达到 `HeatLimit=60`，护盾暂时停用 150 个逻辑帧，期间后续伤害进入本体，恢复计时也暂停。过载结束后护盾重新工作。比较第二、三发时，必须让它们落在这 150 帧内。

普通自愈每 270 帧恢复 25 点；B 区第三辆靶车每 180 帧恢复 25 点。它的初始低护盾只在开局短时间内可见，已补满时可重新开局观察。

D 区空仓装填等待 180 帧，一次恢复 3 发；随后每 90 帧恢复 2 发。按 S 避免补满后立刻再次开火，才能观察完整的 `0→3→5→6`。以上均为逻辑帧，实际等待秒数由游戏速度决定。

## 配置位置与范围

地图 `[VeraFeatures]` 开启 `Shield`、`AresAmmo`、`AresReload`、`AresNoAmmoWeapon`；启动器决定 `Overload`。护盾在 `[SDKLabShield]`、`[SDKLabRecoveryShield]`；过载在 `[VeraOverload]`；弹药标签在各单位与武器节。

这张地图覆盖已接入的基础链，不代表所有 Ares／Phobos 功能均已兼容。没有演示护盾附加／移除、类型转换、护盾事件动画、自定义超级武器或多人联机同步。

启动器的两个边界检查可在插件工程根目录运行：

```sh
python -m unittest discover -s plugins/vera20k-ares/examples/sdk-lab -p test_play.py -v
```

组件 0.4.1 修复了同时开启这些功能时，配置阶段对大量缺省字段重复编码造成的燃料耗尽；未修改 SDK 接口、配置结构或引擎执行预算。已有游戏数值测试与本地图的实机开局检查是不同层次的验证，上表用于逐项人工验收。
