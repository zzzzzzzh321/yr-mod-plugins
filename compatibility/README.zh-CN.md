# Ares 外置兼容台账

本台账用于逐项推进 `vera20k-ares.wasm` 对 Ares 的完整兼容。功能范围、具体限制和完成证据维护在 [ares-features.csv](ares-features.csv)，不要根据组件文件名或少数测试地图推断整体完成。

范围来源是 Ares 3.0 公开文档，以及引擎提交 `d3e66ceca` 中的[中文功能参考](../../engine/docs/zh-CN/ares-feature-guide.md)和 [INI 索引](../../engine/docs/zh-CN/ares-ini-index.csv)。原功能名称、分类、编号及官方链接作为定位信息保留；本台账不复制第三方文档正文。完整参数、默认值、适用对象及上游限制仍需打开每行官方页面核对，必要时检查安装版 Ares 的实际行为。原作者及贡献者见 [Ares Credits](https://ares-developers.github.io/Ares-docs/credits.html)。

## 范围与统计口径

CSV 共 405 行，其中 239 个功能主题、143 项修复、23 个目录或参考入口。功能主题包括恢复的 TS 机制、单位与通用玩法、隐形与探测、武器、抛射体、弹头与伤害、建筑与基地、阵营与国家、超级武器、矿物与资源、资源与配置加载、界面与诊断。143 项修复由 54 项原版缺陷、79 项模组逻辑修复、10 项性能修复组成。

一个主题可能包含多个标签、调用路径和适用对象；一个标签也可能跨越多个主题。不能把条目数或 INI 键数直接转换成兼容百分比。现有 INI 索引只收集正文显式标注节名的关联键，含复用原版键和占位模板，不是完整参数清单。主题中的上游限制、未实现部分和平台条件必须逐项注明，不能擅自扩充为上游不存在的功能，也不能把尚未核对的差异忽略。

引擎 [ares.md](../../engine/docs/ares.md) 记录的 `#[cfg(feature="ares")]` 内置能力属于迁移线索，不等于外置 Wasm 支持。迁移应使用通用宿主接口，将配置解释与扩展决策放入插件，保留原引擎状态与机制所有者。Phobos 血量护盾和自定义过载不计入 Ares 兼容进度；Ares ForceShield 超级武器另按自身主题核对。

## CSV 字段与状态

文件使用带 BOM 的 UTF-8，便于文本工具与表格软件读取。`implementation` 中路径相对插件工程根目录；相邻引擎路径以 `../engine/` 开头，多项用分号分隔。

| 字段 | 含义 |
| --- | --- |
| `id` / `title_zh` | 稳定条目编号和中文功能名，保留来源编号，不重新编号 |
| `category_zh` / `kind` | 分类及 `feature`、`bugfix`、`reference` 类型 |
| `official_url` | 直接指向该主题的 Ares 官方页面 |
| `status` | 下表所列的外置兼容状态 |
| `implementation` | 实际插件入口及共享宿主消费者，避免只登记配置结构 |
| `evidence` | 已检查的源码、行为依据、验证范围及可复现入口 |
| `remaining` | 具体未完成链、上游边界或尚未证明的兼容差异 |
| `verification` | 该行应执行或复核的生产路径与关键边界 |

| 状态 | 使用条件 |
| --- | --- |
| `not_audited` | 尚未核对外置实现与完整行为证据；既不等同确定缺失，也不能计作已支持 |
| `partial` | 已有部分外置实现或集成证据，但仍有功能缺口、接纳差异或不足以证明整行范围的验证 |
| `implemented` | 已完成该行适用范围的配置、决策、消费、生命周期、恢复及必要呈现，并有当前组件和实际引擎路径的证据；限制明确且与上游范围相符 |
| `reference` | 目录、术语、作者或历史资料入口，不作为独立运行能力计算完成率 |

当前参考组件源码为 0.7.0，配置版本5、状态版本1，API v1与WIT不变。AR359、AR272、AR255、AR069 与 AR242 共5项记为 `partial`；377项尚未审计、23项为参考入口。0.5.0已接入建筑有限弹仓的 ROF 策略及四项手动操作标签，并完成其实际组件、冻结配置和相关引擎路径的集中回归。0.6.0移除了`NoAmmoWeapon`仅-1/0/1的人工边界：任意负数关闭、任意非负索引原样发布，实际武器仍由宿主唯一选择/解析所有者处理。有效0..17槽、高槽所需的`TurretCount`读取分支、非Gattling炮手早返回、>=18安全无武器以及建筑延迟开火完整索引已通过实际Wasm与宿主联合回归核对；配套发布构建另通过0.5.0有/无组件两份完整存档的接纳与状态恢复，保留旧组件与冻结配置，拒绝未知格式。此存档检查未覆盖GUI及常驻资源重绑定。

0.7.0只改变新对局的安装默认：加载组件后，已外置的`AresAmmo`、`AresReload`、`AresNoAmmoWeapon`、`AresManualControl`默认启用，可以直接使用原Ares标签；`[VeraFeatures]`中显式`no`仍可分别关闭。Phobos护盾与自定义过载继续默认关闭，过载依赖护盾。各标签自身默认值不变，旧组件和旧非空冻结配置不补入新默认。读档要求当前资源与保存的组件摘要一致，不能把新版组件替换进旧对局。本轮独立通过25项插件侧及91项引擎回归、7种原版资源运行模式和checkfast；ares模式完全不写开启开关，实际开火及资源准入存读档通过。旧0.6组件恢复原关闭策略，新0.7组件接管旧档被拒绝，新默认策略按原组件恢复；这些保存策略检查未覆盖GUI和常驻美术重绑定。隧道、多选治疗步兵及其他既有缺口仍保持`partial`。

## 每项功能的证据规则

1. 从对应官方页面及适用的原始行为出发，核对标签所属文件和节、默认值、缺失/空值/无效值、层次保留、解析器、单位和对象类别。配置解析应继续调用宿主既有读取器。
2. 指出配置解释和可变状态的权威所有者，追踪消费者、初始化、更新、暂停、叠加、移除、销毁、容器或归属变化，以及存档恢复。已有原版机制应复用，不另造竞争状态。
3. 用实际构建的组件经过正式引擎入口验证。能读到键、产生一个策略或通过模拟宿主单测，不能单独证明游戏行为成立。已有内置实现只能作为参考，不能替代外置路径验收。
4. 记录验证覆盖的对象与条件，特别是飞机、建筑、步兵、车辆、驻军、运输、部署及其他扩展接触同一决策点的情况。发现边界时写清触发条件、可见结果和下游风险。
5. 游戏数值、定时与随机流须保留确定性和原有先后顺序。涉及 ROF、随机延迟、目标筛选或随机资源选择时，检查 RNG 抽取次数与顺序；不能只比较最终血量。只有新增或已发现不同的数值链才需要相应原生数值验证，不重复制造整套算法。
6. 证据应给出命令、适用组件/接口版本和检查对象。运行日志、截图、审查记录及编译缓存留在工程外的 `work`，不提交到源码；台账保留结论、边界和可复现入口。

`implemented` 不是永久标签。若接口、算法、资源绑定或恢复路径变化使原证据不再覆盖，应回到 `partial` 并补验证。目标是否完成必须覆盖整张台账的适用功能和修复，不能以某轮新增的一小条链代替完整目标。旧 DLL 的平台或性能修复由相应引擎所有者给出等价行为或适用性证据，不照搬注入方式，也不未经核对就跳过该行。

## 验证矩阵

| 场景 | 必须确认的内容 |
| --- | --- |
| 原版无组件 | 保持原版读取、状态、时钟和调用路径，扩展不会静默生效 |
| 新对局安装组件、无Ares启用开关 | 原Ares标签直接生效，已接入的无标签安装修复生效；无手动限制标签时不限制输入，Shield/Overload仍关闭 |
| 组件已加载但对应功能显式关闭 | 用`[VeraFeatures] ...=no`核对回退及后层保留；四个Ares模块独立，关闭一项不代表其余也关闭；内置`ares`构建特性须单独区分 |
| 功能启用 | 读取、绑定与实际消费接通，验证正常路径及该机制的重要边界 |
| 旧组件 | 新宿主正确处理缺少可选回调或字段的旧产物，缺省值不暗中改变旧对局；新组件的最低宿主要求明确 |
| 存档恢复 | 当前作品须提供相同组件摘要，再使用保存的原组件字节和冻结配置重建派生策略；当前INI与新默认不能覆盖旧对局，计时器和状态延续正确 |
| 随机流与联机 | 相同状态和输入保持同样的抽取及更新顺序，检查必要的锁步状态、哈希和网络路径，不能由离线开局推断联机已兼容 |

为逐标签功能保留最小验收样例，但样例不能替代完整类别和生命周期核对。相关功能成批实现、集中编译回归，每项仍须追踪完整消费与生命周期，不为了测试容易通过而删去目标范围。

## 开发优先队列

1. 先收敛已有 Ammo 链在建筑和步兵上的残留，包括有限建筑弹仓的 ROF、普通/空仓装填、资格与例外、每发成本、备用武器和恢复路径。ROF 继续由既有 `get_rof` 所有者计算，插件提供受校验的通用策略；不能把算法复制到 Wasm 或伪造弹量绕过分支。无标签安装修复与武器 `Ammo` 标签分别登记，补一处不能提前宣布所有弹药兼容完成。
2. 按完整机制迁移已有内置 Ares 能力。先核对原实现和缺口，明确所需通用接口、状态所有者和消费链，再选择下一项，不按文件数量拆任务。内置和外置路径不能长期拥有两份独立状态或互相覆盖的决策。
3. 超级武器按充能、条件判定、目标选择、消耗、执行、事件、呈现和恢复整条链接入，复用超武、经济、单位生成等领域所有者，不能靠对象 `tick` 拼凑超武。EMP、AttachEffect、所有权、运输和类型转换同样要经过各自领域入口。
4. 资源、声音、光标、菜单、加载画面和诊断能力走对应应用及资源接口。原版缺陷修复归原引擎所有者；需要保留的历史兼容差异再由通用策略选择，避免把原版引擎改成只适用于 Ares 的专用宿主。

每完成一条链，更新相关行的实际实现位置、验证入口、结果及剩余限制。未经用户授权不推送、上传或公开工程和验收资源。
