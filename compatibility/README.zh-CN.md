## 按分类推进与集中验收

后续沿用功能目录的分类推进。每个分类拆成若干编写批次，分类内连续实现相关功能，共用的 SDK、类型投影和状态所有者统一接入；编写期间及时修复编译错误，分类收尾时集中运行该类功能、原版与旧组件对照、存读档和跨功能交互回归，再整理本地交付。不再为每个小功能单独构建游戏程序和制作版本包。

后续目标为完整Ares兼容，按全部官方功能与修复台账推进，同时补齐已有子链缺口和原基线没有的能力。0.28的既有机制迁移是已完成的阶段。当前不开展新的Phobos功能迁移。

当前继续推进超级武器分类的AR297／AR310／AR315及共用前置；本轮补充固定EVAMD语音引用、现有处理器的语音生命周期，以及持续放电发射完成流程；其它处理器覆写和完整呈现继续保持独立缺口。武器／抛射体和其它分类的剩余项仍按台账继续收敛。已有能力也须按各行 `remaining` 继续收敛，不能因重新登记为 `partial` 就跳过其完整兼容要求。文档、代码接入、编译、实际组件／游戏验收分别记录，未验收的范围保持原状态；跨分类的解析器、注册表、时钟及状态所有者继续共用。

启动资源实现位于 [resources/startup.rs](../plugins/vera20k-ares/src/features/resources/startup.rs)，覆盖0.28已验收的Include、附加音频目录与CSF子链；阵营、界面及超武分别由同一[功能领域目录](../plugins/vera20k-ares/src/features/)维护。完整主题范围以CSV各行的实现和限制为准，当前构建与配套方式见[独立开发指南](../sdk/dev-kit/README.zh-CN.md)。

## 每项功能的证据规则

1. 从对应官方页面及适用的原始行为出发，核对标签所属文件和节、默认值、缺失/空值/无效值、层次保留、解析器、单位和对象类别。配置解析应继续调用宿主既有读取器。
2. 指出配置解释和可变状态的权威所有者，追踪消费者、初始化、更新、暂停、叠加、移除、销毁、容器或归属变化，以及存档恢复。已有原版机制应复用，不另造竞争状态。
3. 用实际构建的组件经过正式引擎入口验证。能读到键、产生一个策略或通过模拟宿主单测，不能单独证明游戏行为成立。已有内置实现只能作为参考，不能替代外置路径验收。
4. 记录验证覆盖的对象与条件，特别是飞机、建筑、步兵、车辆、驻军、运输、部署及其他扩展接触同一决策点的情况。发现边界时写清触发条件、可见结果和下游风险。
5. 游戏数值、定时与随机流须保留确定性和原有先后顺序。涉及 ROF、随机延迟、目标筛选或随机资源选择时，检查 RNG 抽取次数与顺序；不能只比较最终血量。只有新增或已发现不同的数值链才需要相应原生数值验证，不重复制造整套算法。
6. 证据应给出命令、适用组件/接口版本和检查对象。运行日志、截图、审查记录及编译缓存留在工程外的 `work`，不提交到源码；台账保留结论、边界和可复现入口。

`implemented` 不是永久标签。若接口、算法、资源绑定或恢复路径变化使原证据不再覆盖，应回到 `partial` 并补验证。目标是否完成必须覆盖整张台账的适用功能和修复，不能以某轮新增的一小条链代替完整目标。旧 DLL 的平台或性能修复由相应引擎所有者给出等价行为或适用性证据，不照搬注入方式，也不未经核对就跳过该行。

## 验证矩阵

| 场景 | 必须确认的内容 |
| --- | --- |
| 原版无组件 | 保持原版读取、状态、时钟和调用路径，扩展不会静默生效 |
| 新对局安装组件、无Ares启用开关 | 原Ares标签直接生效，已接入的无标签安装修复生效；无手动限制标签时不限制输入，Shield/Overload仍关闭 |
| 组件已加载但对应功能显式关闭 | 用`[VeraFeatures] ...=no`核对回退及后层保留；各Ares模块独立，关闭一项不代表其余也关闭；内置`ares`构建特性须单独区分 |
| 功能启用 | 读取、绑定与实际消费接通，验证正常路径及该机制的重要边界 |
| 旧组件 | 新宿主正确处理缺少可选回调或字段的旧产物，缺省值不暗中改变旧对局；新组件的最低宿主要求明确 |
| 存档恢复 | 当前作品须提供相同组件摘要，再使用保存的原组件字节和冻结配置重建派生策略；当前INI与新默认不能覆盖旧对局，计时器和状态延续正确 |
| 随机流与联机 | 相同状态和输入保持同样的抽取及更新顺序，检查必要的锁步状态、哈希和网络路径，不能由离线开局推断联机已兼容 |

为逐标签功能保留最小验收样例，但样例不能替代完整类别和生命周期核对。相关功能成批实现、集中编译回归，每项仍须追踪完整消费与生命周期，不为了测试容易通过而删去目标范围。

## 开发优先队列

1. 先收敛已有 Ammo 链在建筑和步兵上的残留，包括有限建筑弹仓的 ROF、普通/空仓装填、资格与例外、每发成本、备用武器和恢复路径。ROF 继续由既有 `get_rof` 所有者计算，插件提供受校验的通用策略；不能把算法复制到 Wasm 或伪造弹量绕过分支。无标签安装修复与武器 `Ammo` 标签分别登记，补一处不能提前宣布所有弹药兼容完成。
2. 按分类推进完整Ares兼容，当前已集中验收AR360／AR362普通开火、AR267／AR367普通航程与AR268普通Airburst／Splits子链；0.32已接通AR265普通散布上下界；0.33已接通普通Primary的Weapon同名实例、冻结策略与飞行/恢复前置；0.34已接通该Airburst子链并保持child+130为空；0.35已接通上述普通Shrapnel引用/安装语义；0.36已接通核弹发射井/直接载荷与NukeMaker的实际关联且保留裸构造预算；下一链先收敛共同射程物理读取及原谓词，再处理核弹光照/预影响动画/共享调色板和EVA，不向其它直接构造器擅自注入预算。已有内置链先核对实际消费和缺口；原基线没有的能力依据官方范围与安装版行为接入。每批明确通用接口、唯一状态所有者和验证范围，内置和外置路径不能长期拥有两份状态或相互覆盖决策。
3. 超级武器按充能、条件判定、目标选择、消耗、执行、事件、呈现和恢复整条链接入，复用超武、经济、单位生成等领域所有者，不能靠对象 `tick` 拼凑超武。EMP、AttachEffect、所有权、运输和类型转换同样要经过各自领域入口。
4. 资源、声音、光标、菜单、加载画面和诊断能力走对应应用及资源接口。原版缺陷修复归原引擎所有者；需要保留的历史兼容差异再由通用策略选择，避免把原版引擎改成只适用于 Ares 的专用宿主。

每完成一条链，更新相关行的实际实现位置、验证入口、结果及剩余限制。未经用户授权不推送、上传或公开工程和验收资源。
